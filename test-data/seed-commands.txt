HWAI Agent - Mock Data Seed Commands
=====================================

วิธีใช้:
1. รัน npm run dev แล้วเปิด http://localhost:3000
2. กด F12 เปิด DevTools -> แท็บ Console
3. Copy คำสั่งด้านล่าง (ทำ Curriculum ก่อน Courses จะได้ลิงก์ตรงกัน) วางแล้ว Enter
4. หน้าจะ reload อัตโนมัติ

[3b] นักศึกษา - ไม่ต้องใช้ console

  - test-data/students_sample.csv   (นักศึกษา, 30 แถว — 25 ใช้ได้ปกติ + 5 แถวตั้งใจใส่ผิดไว้โชว์ validation ของหน้านี้)

    ต่อเลขให้ไม่ชนกัน ยกเว้นแถวสุดท้ายที่ตั้งใจให้ชนตรงๆ — ทำ [5] ก่อนถึงจะเห็นผลข้อ 5 ด้านล่างชัด:
    1. studentId ว่างช่อง program (69070119)   -> "ขาด: program"
    2. studentId สั้นแค่ 6 หลัก (690701)         -> "รหัสนักศึกษาต้องเป็นตัวเลข 8 หลัก"
    3. อีเมลรูปแบบผิด "not-an-email" (69070120)  -> "อีเมลไม่ถูกต้อง"
    4. อีเมลไม่ตรงกับ studentId (68020111)        -> "อีเมลต้องเป็น รหัสนักศึกษา@kmitl.ac.th"
    5. studentId ซ้ำกับคนที่มีอยู่แล้ว (69070101, ต้องทำ [5] ก่อน) -> แถวนี้จะไม่ error ในตาราง preview
       (แอปยังไม่ tag ว่า error ตรงนี้) แต่จะไม่ถูกนับใน "ใหม่ N" และไม่ถูก import จริง — เป็นพฤติกรรมเดิมของแอป

(อาจารย์ใช้ [3] ด้านบนแทน CSV import เพราะต้องผูก courseId ด้วย ถ้าอยากได้อาจารย์เปล่าๆ ไม่ผูกวิชา ค่อยใช้ CSV import teachers_sample.csv แทน)

[5] นักศึกษาครบ flow — cohort + ลงทะเบียนวิชา + หมวดคะแนน + งาน + rubric + ผลตรวจ
    (ต้องทำ [2] ก่อน เพราะลงทะเบียนเข้า c-mock-1 "การเขียนโปรแกรมคอมพิวเตอร์" ของสมศักดิ์)
    15 คนใน cohort (CE67/68/69/70, 1 คน inactive) — 3 คนแรก (69070101-103) ลงทะเบียนวิชา c-mock-1 จริง
    อีก 11 คนที่เหลือ (69070104-108, 68020101-104, 67010101, 70010101-102) ยังไม่ลงวิชาไหนเลย
    — ไว้ใช้ทดสอบการ import นักศึกษาเข้าวิชา ดู [7] ด้านล่าง
    วิชานี้มี 3 หมวดคะแนน (งานที่มอบหมาย 40% / สอบกลางภาค 25% / สอบปลายภาค 35% — ยังไม่มีงานผูกกับ
    2 หมวดหลัง เป็นของจริงที่ยังไม่ได้สร้าง ไม่ใช่ bug) และ 3 งาน ทุกงานอยู่ในหมวด "งานที่มอบหมาย"
    ทุกงานมี rubric ผูกอยู่แล้ว (ทุกงานที่สร้างผ่าน UI จะมี rubric เสมอ):
                     [1] งานเดี่ยว ครบกำหนดแล้ว มี rubric 3 ข้อ + ผลตรวจ 3 แบบ (ตรวจแล้ว/รอตรวจ/ยังไม่ตรวจ)
                     [2] งานเดี่ยว ยังไม่ถึงกำหนด มี rubric 3 ข้อ ยังไม่มีใครส่ง
                     [3] งานกลุ่ม (a-mock-3, จับคู่ 2 คน) ยังไม่ถึงกำหนด มี rubric 3 ข้อ ยังไม่มีทีม/ใครส่ง
                         — ไว้ทดสอบ flow จับกลุ่ม: login 69070101 จับทีมกับ 69070102 → ส่งงาน →
                         login somsak.c@kmitl.ac.th (ทำ [3] ก่อนถึงจะ login ได้) → Start Grading
                         หรือกด Review/Recheck (ตอนนี้มี rubric แล้ว หน้า Grading Review จะเห็นเกณฑ์จริง)
                         → ให้คะแนนครั้งเดียว ทั้ง 69070101 และ 69070102 ได้คะแนนพร้อมกัน
    ล็อกอินเป็นนักศึกษาด้วยอีเมล 69070101@kmitl.ac.th (รหัสผ่านอะไรก็ได้ 4 ตัวขึ้นไป) จะเห็นวิชา+งานนี้
    และหน้า "ผลการประเมิน" จะโชว์ยอดรวมถ่วงน้ำหนักจริง (90/100 ในหมวด 40% -> Total so far 36.0%)

fetch('/mock-data/student-flow-mockup.json').then(r=>r.json()).then(d=>{localStorage.setItem('hwai_cohort_students_v1', JSON.stringify(d.cohortStudents)); localStorage.setItem('hwai_students_v1', JSON.stringify(d.courseStudents)); localStorage.setItem('hwai_grading_categories_v1', JSON.stringify(d.gradingCategories)); localStorage.setItem('hwai_assignments_v1', JSON.stringify(d.assignments)); localStorage.setItem('hwai_rubrics_v1', JSON.stringify(d.rubrics)); localStorage.setItem('hwai_submissions_v1', JSON.stringify(d.submissions)); if(!localStorage.getItem('hwai_student_groups_v1')) localStorage.setItem('hwai_student_groups_v1', '[]'); location.reload();});

หมายเหตุ:
- ไฟล์ json ต้นทางอยู่ใน public/mock-data/ (courses-mockup.json, curriculum-mockup.json, teachers-mockup.json, student-flow-mockup.json)
  ถ้าแก้ข้อมูล mock ให้แก้ที่ test-data/*.json ก่อน แล้ว copy ทับไฟล์ใน public/mock-data/ ด้วย
- คำสั่งพวกนี้ทำงานเฉพาะตอน dev server รันอยู่ (npm run dev) เพราะ fetch ไปที่ localhost
- teachers-mockup.json ใช้ courseId ที่ตรงกับ courses-mockup.json (c-mock-1..6) ทำ [2] ก่อน [3] เสมอ
- student-flow-mockup.json ก็ใช้ courseId c-mock-1 เหมือนกัน ทำ [2] ก่อน [5] เสมอ
- students_sample.csv ([3b]) กับ course-import-test.csv ([7]) เป็นคนละไฟล์ คนละหน้า แต่ ID ใช้ scheme เดียวกัน:
  — [3b] คือ import นักศึกษาเข้า cohort กลางของระบบ (ผ่าน /admin/users, format 6 คอลัมน์ studentId,firstName,lastName,email,cohort,program)
  — [7] คือ import นักศึกษาที่มีอยู่ใน cohort แล้ว เข้าไปลงทะเบียนวิชาใดวิชาหนึ่ง (ผ่านหน้า course ของอาจารย์, format 4 คอลัมน์ student_id,first_name,last_name,email)
  — ทำ [3b] เสร็จแล้ว คนที่เพิ่งนำเข้ามา (เช่น 69070109-118) ก็เอาไปใส่ใน CSV แบบ [7] เพื่อทดสอบ import เข้าวิชาต่อได้เลย

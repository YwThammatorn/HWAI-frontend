# Design Stability Audit — HWAI Agent (21/10/2569)

ตรวจจากโค้ดจริง (`src/`, 37 หน้า, 3 role) ด้วยหลัก HCI/UX: Nielsen #4 *Consistency & standards*, #1 *Visibility of system status*, #5 *Error prevention*, Gestalt (similarity/proximity), WCAG 2.2 AA, และหลักของ design system (single source of truth). "Design stability" ในที่นี้ = **หน้าตาและพฤติกรรมของ UI เดิม ๆ ยังเหมือนเดิมเมื่อข้ามหน้า ข้าม role และข้ามเวลา** — คนใช้เรียนรู้ครั้งเดียวแล้วคาดเดาได้

> วัดจากการนับในโค้ด (ตัวเลขด้านล่างเป็นของจริง) ไม่ได้วัด CLS/ประสิทธิภาพบน browser และไม่ได้ทดสอบกับผู้ใช้จริง

## สรุป 1 ย่อหน้า

โครงสร้างพื้นฐาน **ค่อนข้างมั่นคง**: มี `DESIGN.md`, token สี/สถานะ (`--s-*`, `--st-*`), component กลาง (`Modal`, `SidebarParts`, `SortableTh`, `CourseBanner`), test กันขนาดตัวอักษร (`font-scale.spec`) และกติกา "ห้าม action ที่โผล่เฉพาะตอน hover". จุดที่ **ยังไม่นิ่ง** คือชั้นล่างลงมา — สีเทา/ฟ้าปนกันในหน้าฟอร์ม, หัวหน้าแต่ละหน้าเขียนเอง, กล่องยืนยันมี 2 แบบ, focus ring ไม่ครบ, และคำเรียก "Assignment" ในภาษาไทยมี 3 คำ

## ข้อค้นพบ (เรียงตามผลกระทบต่อผู้ใช้)

### 1. คำเรียก "Assignment" ในภาษาไทยมี 3 คำ — 🔴 สูง (Nielsen #4)
- sidebar/นักศึกษา: **งาน/การบ้าน** · breadcrumb และปุ่มในหน้าอาจารย์ (assignments, new, edit, grading): **ชิ้นงาน** (51 จุด / 12 ไฟล์) · ที่อื่น: **การบ้าน**
- ผลกระทบ: ผู้ใช้ต้องตีความว่าเป็นของอย่างเดียวกันหรือไม่ — เป็นความไม่นิ่งที่ผู้ใช้ *เห็นจริงที่สุด* และแก้ถูกที่สุด
- แก้: เลือกคำเดียวต่อ role (แนะนำ **งาน** ทั้งระบบ เพราะสั้นและตรงกับ "ตรวจงาน"/"ส่งงาน" ที่ใช้อยู่แล้ว) แล้วทำเป็นพจนานุกรมสั้น ๆ ใน `DESIGN.md` · งาน ~½ วัน + test กัน regress

### 2. ฟอร์มปนสีเทา-กลางกับสีฟ้า-เทาของระบบ — 🟡 กลาง (Gestalt similarity)
- `border-gray-200` = #E5E7EB (เทากลาง) แต่ `--border` = #C8D6E0 (เทาอมฟ้า) → ในหน้าเดียวกันเห็นเส้นขอบ 2 โทน เช่น New/Edit Assignment (29/33 จุด), recheck (35), RubricCriteriaEditor (42)
- ทั้งระบบ: Tailwind palette ตรง ๆ **532 จุด / 28 ไฟล์**, hex เขียนตรง **147 จุด / 30 ไฟล์** (ส่วนใหญ่อยู่ใน login/register/not-found และหน้าที่ปิดด้วย flag เช่น history/dashboard)
- โค้ดที่ผมเขียนวันนี้ (`LatePolicyEditor`) ก็ใช้ gray แบบเดียวกับฟอร์มข้างเคียงเพื่อให้เข้ากับหน้า — เป็นส่วนหนึ่งของหนี้นี้
- แก้: ทำ alias ใน `globals.css` ให้ `border-gray-200/100` → `--border/--border-subtle` (ทำ rule เดียวแบบที่ทำกับ `text-gray-400/500` อยู่แล้ว) แล้วทยอยเก็บ hex ใน login/register · งาน ~½–1 วัน, ความเสี่ยงต่ำ

### 3. กล่องยืนยันมี 2 แบบ — 🟡 กลาง (Nielsen #5, #4)
- `Modal` กลางมีแล้ว (DESIGN.md §9a) แต่ยังมี `window.confirm/alert` **24 จุด / 16 ไฟล์** (ลบ CLO, ออกจากฟอร์มที่ยังไม่บันทึก ฯลฯ) — หน้าตาเป็นของ browser, ภาษาตาม OS, ใส่คำอธิบายผลกระทบไม่ได้
- แก้: ทำ `ConfirmModal` (ชื่อ, ผลกระทบ, ปุ่มสีตามความอันตราย) แล้วแทนที่ทีละกลุ่ม; กล่อง "ออกจากหน้านี้" ของ `beforeunload` ต้องคงของ browser (เปลี่ยนไม่ได้)

### 4. หัวหน้าไม่เป็น component เดียว — 🟡 กลาง
- `PageHeader` มี แต่ใช้ **2 จาก 37 หน้า**; ที่เหลือเขียน `<h1>` เอง → ขนาดตัวอักษรเท่ากัน (test ล็อกไว้) แต่ระยะ/ตำแหน่งปุ่มหลัก/breadcrumb ไม่เท่ากัน
- แก้: ย้ายหน้าที่ใช้รูปแบบ "ชื่อ + ปุ่มหลักด้านขวา" มาใช้ `PageHeader` · ทำทีละ role

### 5. Focus ring ไม่สม่ำเสมอ — 🟡 กลาง (WCAG 2.4.7)
- `focus-visible` อยู่ใน 44 ไฟล์ แต่หน้าเก่า (หน้ารายวิชา, students, assignments list ฯลฯ) พึ่งค่าเริ่มต้นของ browser → ผู้ใช้คีย์บอร์ดเจอ ring หน้าตาต่างกัน/มองไม่เห็นบนพื้นสี
- แก้: base rule เดียวใน `globals.css` (`:where(a,button,input,select,textarea):focus-visible { outline: 2px solid var(--accent-bright); outline-offset: 2px }`) แล้วลบของซ้ำทีหลัง · งานเล็ก ผลกว้าง

### 6. ขนาดตัวอักษรเขียนเป็น px ตรง ๆ 126 จุด — 🟢 ต่ำ
- ladder ถูกล็อกด้วย test แล้ว แต่ `text-[10px]`/`text-[11px]` ใช้กับ label เล็ก (admin/users 8, admin/courses 14) — บางจุดต่ำกว่า 12px ซึ่งอ่านยากในภาษาไทย (สระ/วรรณยุกต์เล็ก)
- แก้: เพิ่ม step `text-2xs` (12px) ใน scale แล้วแทน

### 7. สิ่งที่ **มั่นคงดีแล้ว** (ควรรักษา)
- สถานะงาน/คะแนนใช้ `--st-*`/`--s-*` ชุดเดียวทั้ง 3 role และมีกฎ "ห้ามใช้ `--bg-subtle` เป็นพื้นนิ่ง"
- Sidebar 3 role ใช้ `SidebarParts` ร่วม (ความกว้าง/ระยะ/แถบ active เหมือนกัน)
- ฟอร์มมี guard "ยังไม่บันทึก" ทุกหน้าสร้าง/แก้ + Modal ปิดด้วย Esc/คลิกนอก
- ปุ่ม action ไม่ซ่อนใน hover (ใช้ได้บนมือถือ/คีย์บอร์ด)
- วันที่ผ่าน `dateLocale` (ตาม TH/EN) · ข้อความทุกจุดผ่าน `t()`
- มี test 900+ ข้อ — เปลี่ยน token/คอมโพเนนต์แล้วรู้ทันทีว่าอะไรพัง

## ลำดับที่แนะนำ (คุ้มที่สุดก่อน)
1. **พจนานุกรมคำไทย + เปลี่ยน "ชิ้นงาน"** (เห็นผลชัด, ต้นทุนต่ำ)
2. **alias เส้นขอบเทา → token + base focus ring** (2 กฎใน `globals.css`, ครอบทั้งแอป)
3. `ConfirmModal` แทน `window.confirm`
4. ย้ายหน้าไปใช้ `PageHeader`
5. step ตัวอักษรเล็ก 12px

## สิ่งที่ยังไม่ได้ตรวจ (ต้องใช้ browser/ผู้ใช้จริง)
- Layout shift ตอนโหลดข้อมูลจาก API (ตอนนี้ข้อมูลมาจาก localStorage จึงไม่เห็นปัญหานี้ — จะเห็นเมื่อต่อ backend)
- ความกว้างจอแคบ (<768px) ของหน้าอาจารย์ — ออกแบบเน้น desktop
- ทดสอบ usability กับอาจารย์/นักศึกษาจริง (5 คนต่อ role พอจะเห็น ~80% ของปัญหา)
